1 · Performance (rua real)

1.1 Orçamento de carga (targets)

MétricaMetaPor quê
LCP (Largest Contentful Paint)< 1,8s no 4GHero + primeiro post legíveis na hora
INP (Interaction to Next Paint)< 200msToque no scrap / nav sem lag
CLS< 0,05Mapa e cards sem “pulo”
JS inicial (comprimido)< 90 KBAndroid de entrada
CSS críticoinline < 14 KBFirst paint sem bloquear
Time to Interactive (mapa)< 3sLeaflet lazy após Feed

1.2 Rede & assets perf

  • Imagens em AVIF/WebP com presets já no repo (encode-avif.sh)
  • srcset + sizes por contexto (avatar / feed / hero)
  • CDN com cache longo + immutable em hash de arquivo
  • Prefetch de rotas: profile.html no idle após login
  • Service Worker: cache do shell + último feed/spots (offline na rua)

1.3 JavaScript perf

  • Modularizar em ES modules (dívida técnica do status)
  • Code-split: mapa e marketplace só sob demanda
  • Virtualizar lista do feed se > 40 posts
  • Debounce de geoloc + batch de writes Supabase
  • Remover mocks do caminho crítico em prod

1.4 Backend / dados perf

  • Índices já no schema; revisar explain em posts + scraps
  • Realtime só em spots/afters — não no feed inteiro no dia 1
  • Edge functions leves para rate-limit da caixinha
  • Região sa-east-1 (já alinhada)
  • Payload de posts: select mínimo + contagem de likes em view

1.5 Observabilidade perf

  • Web Vitals → endpoint próprio ou GA4/Plausible
  • RUM por device (iPhone vs Android entrada)
  • Alertas se LCP p95 > 3s no fim de semana do evento
  • Feature flags para desligar animações sob CPU alta

2 · Estética (identidade de rua)

2.1 Sistema visual “cartaz vivo”

  • Design tokens fechados: cor, tipo fluida, sombra-cartaz, motion (já em andamento)
  • Presets de perfil (“stencil rosa”, “noite preta”, “ocre cartaz”) — fase 2 do PDF
  • Tipografia: manter Saira Stencil + Oswald; subset de fontes (só glyphs usados)
  • Fotografia do evento com tratamento film grain + contraste de rua
  • Modo claro que não “parece app genérico” — papel e ocre, não branco hospital

2.2 Motion com propósito estética

  • Manter fasc-motion + CSS tokens; evitar libs pesadas
  • Scroll-driven só onde agrega (já explorado)
  • Respeitar always prefers-reduced-motion
  • Transições de rota coerentes index ↔ profile
  • Microinterações em botões/inputs (já base)

2.3 Som & háptica estética

  • Clicks sutis opt-in (UI sound pack curto, < 30 KB)
  • navigator.vibrate em confirmar after (opt-in)
  • Nada automático no load — silêncio é o padrão

4 · Checklist técnico “melhor do Brasil”

  • ☐ Lighthouse mobile ≥ 90 Performance / ≥ 95 Accessibility / ≥ 95 Best Practices
  • ☐ a11y-check.py + axe no CI (já existe base)
  • ☐ Teste em device real: Android 4–6 GB RAM + iPhone
  • ☐ Teste com throttling Fast 3G e CPU 4× slowdown
  • ☐ Mapa: tiles com cache; markers cluster se densos
  • ☐ Zero service_role no client (princípio do PDF)
  • ☐ Content-Security-Policy apertada em prod
  • ☐ Fonts self-hosted com font-display: swap + subset
  • ☐ Critical CSS extraído; resto async
  • ☐ Error boundary visual (“a rua falhou, tenta de novo”) — sem tela branca

5 · Sequência sugerida (sprints)

Sprint A — Ship do evento

Auth QA · Feed real · Scraps · Afters · fasc-prod · RLS · PWA mínima offline.

Sprint B — Velocidade

Split do mapa · imagens AVIF · SW cache · Web Vitals · virtual list se precisar.

Sprint C — Beleza social

Caixinha · handles · tema de perfil · polish motion · export de memórias (zine PDF).
